# 让 DSH 的侧边栏启动时默认折叠

## 这是什么

DSH 的左侧栏（会话列表那一栏）**每次启动都是展开的**，录屏时会把你的会话列表拍进去。
这个补丁把它改成**启动时默认收起**，需要时按 `Ctrl+B` 随时展开。

## 怎么用

1. **双击 `修补.bat`**
2. 脚本会发现 DSH 正在运行，问你「现在就自动关闭 DSH 并继续吗？(Y/N)」
   —— 输入 `Y` 回车（**你的会话是自动保存的，重开 DSH 后可以继续**）
3. 脚本自动：关闭 DSH → 备份 → 改文件 → 自检
4. 看到「修补完成」后，**重新启动 DSH**，侧边栏就是收起的

## 怎么还原

双击 **`还原.bat`**（要先退出 DSH）。它会用备份把 `app.asar` 换回去。

## 它到底改了什么

DSH 的界面布局状态**没有做持久化**（我查过：`redux-persist` / `electron-store` 全部 0 命中，
`localStorage` 只用于"终端绑定"），所以每次启动都会回到写死的初始值。补丁改的就是那一行：

```
文件：dsh/node_modules/@deepseek-ai/dsh-client-ui-layout/lib/client.js
  （在 app.asar 内，31732 字节）

原始：layoutInfo: { sidebar: 280, viewportWidth: window.innerWidth, … }
改后：layoutInfo: { sidebar: 0,   viewportWidth: window.innerWidth, … }
```

`sidebar` 是左栏宽度，`280` 是展开宽度，`0` 就代表折叠
（代码里的判断是 `sidebarCollapsed = narrow ? !narrowExpanded : layoutInfo.sidebar === 0`）。

**替换是严格等长的**（`"sidebar: 280,"` → `"sidebar: 0,  "`，都是 13 字节），
所以 asar 内部所有偏移量都不变，不用重新打包。

## 为什么还要改 SHA256

DSH 的 `app.asar` 里 **11470 个文件全部带完整性记录**：

```json
"integrity":{"algorithm":"SHA256","hash":"980ab8c5…","blockSize":4194304,"blocks":["980ab8c5…"]}
```

只改内容不改 hash，一旦 Electron 启用了 `EnableEmbeddedAsarIntegrityValidation`，
DSH 会**直接启动失败**。所以补丁脚本会：

1. 改内容
2. 重算该文件的 SHA256
3. 把新 hash **等长**写回 asar 头部的 `hash` 和 `blocks[]`（64 个十六进制字符，长度不变）

这样无论校验 fuse 开没开，都能正常启动。

## 脚本每次都做这些自检（任一不过就自动还原）

- 文件总大小不变
- 差异只落在目标文件区间和 header 区间内（区间外变更字节数必须为 0）
- 目标文件里已搜不到原串、能搜到新串
- **重新解析 header，核对新 hash 与实际文件内容一致**（最关键的一条）
- 改后的 JS 能通过语法检查（离线验证时做过，`node --check` exit 0）

## 风险与注意

- **DSH 升级或重装会覆盖 `app.asar`，补丁随之失效**，需要重跑一次 `修补.bat`
- 备份留在 `app.asar.bak-before-sidebar-fold`，还原脚本依赖它，**别删**
- 万一 DSH 起不来：退出 DSH → 双击 `还原.bat` → 再启动即可
- 如果 DSH 装在别的位置，改 `patch-sidebar.ps1` 里的 `$ASAR` 路径

## 快捷键备忘

| 操作 | 快捷键 |
|---|---|
| 展开 / 收起左侧栏 | `Ctrl + B` |
| 窗口宽度 < 1024px 时 | 侧边栏自动收成窄条（`SIDEBAR_AUTO_COLLAPSE = 1024`） |
